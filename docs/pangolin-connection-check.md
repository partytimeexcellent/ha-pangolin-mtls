# Connect Pangolin and install the CA

The Pangolin setup is in **Pangolin setup** in the Home Assistant app. It uses Pangolin’s integration API to list public resources and upload this app’s public CA certificate to the resource you select. Normal device access, local certificate issuance and expiry reminders do not need an API key.

1. For self-hosted Pangolin, follow [Pangolin’s integration API setup](https://docs.pangolin.net/self-host/advanced/integration-api): set `enable_integration_api: true` under `flags:` in `config.yml`, restart Pangolin, and configure `int-api-router` in `config/traefik/dynamic_config.yml` to route its `Host(...)` hostname to the integration listener. In **Pangolin setup**, enter `https://YOUR_API_HOST`; the app adds `/v1`. For Cloud, enter `https://api.pangolin.net`. See the [installation guide](installation.md#3-enable-pangolins-integration-api).
2. Create an organization API key with **Get Organization**, **List Organization Domains**, **List Sites**, **Get Resource**, **List Resources**, **List Targets**, **Get Resource Policy**, and **Update Resource Policy**. Find the organization ID in Pangolin’s organization settings or dashboard URL.
3. Create the CA in this app’s **Device certificates** section. In Pangolin, create a dedicated HTTPS public resource for Home Assistant with an inline policy. You can leave its resource and target disabled while preparing it.
4. In **Pangolin setup**, enter the Pangolin Organization ID and API key, then select **Find public resources**. For example, `https://pangolin.domain.com/organizationid/settings/api-keys` has ID `organizationid`. Find the intended hostname and select **Install CA cert**. The app checks its identity, policy, hostname and trust first. It refuses shared policies and conflicting or incomplete hostname results. A repeated selection reports **Already installed**.
5. If the resource is disabled, optionally select **Enable mTLS after installing the CA**. The app updates the selected inline policy and verifies the setting. Otherwise enable **Client Certificate (mTLS)** in Pangolin under **Authentication → Other Methods**. An active resource must be disabled before this app turns on mTLS.
6. After importing a device certificate and enabling the prepared target/resource, confirm a new client without a certificate is rejected and the enrolled device connects over the intended external network. API success alone does not prove TLS enforcement.

The key remains only in this page’s memory while it is open. Update Resource Policy grants broader policy changes in Pangolin; use a temporary key and revoke it after setup. If upload reports an uncertain result, inspect trusted CAs in Pangolin before retrying. The app never sends its CA private key, device identity or package password to Pangolin. It never removes a trusted CA. Removing Pangolin’s final trusted CA disables mTLS.

See [research evidence](research.md#exact-public-api-inventory) and [Pangolin’s mTLS guide](https://docs.pangolin.net/manage/access-control/mtls).
